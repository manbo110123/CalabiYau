# S24：将正式二次元模型替换到 VisualRoot

## 可见成果

正式角色模型进入联网 Character Prefab，脚底、高度、朝向、阴影和材质正确；LogicRoot、Capsule、CameraTargets 和网络组件不需要重做。

## 开始前你要准备

- S04 已检查过的 Humanoid 模型与 Avatar；
- 角色正面、侧面和骨骼预览截图；
- 材质/贴图来源与许可记录；
- 能接受第一轮先关闭复杂头发、裙摆 Cloth 的方案。

## 我负责完成

- 检查模型导入设置、Avatar、材质和 URP 兼容性；
- 为 VisualRoot 建立模型适配组件或明确的局部偏移；
- 检查角色高度与 Capsule 的关系；
- 处理本地角色可能需要的相机遮挡/淡化接口；
- 保留占位模型回退方式；
- 给脚底、头顶、视线点和 Capsule 画对齐 Gizmo。

## 你在 Unity 中操作

1. 打开 Character Prefab Mode。
2. 在 `VisualRoot/ModelRoot` 下放入模型 Prefab 或 FBX 实例。
3. 只调 `ModelRoot` 或专门的 ModelOffset，不修改 LogicRoot 来迁就模型。
4. 让脚底落在逻辑地面高度，模型正面与项目 Forward 约定一致。
5. 把角色 Animator 拖入表现组件字段。
6. 检查所有 SkinnedMeshRenderer 的材质和阴影设置。
7. 保存 Prefab，回到 CharacterLab 查看近景、远景和背光。

## 人工验收

- 站立脚底与地面没有明显悬空/下陷；
- 胶囊覆盖躯干但不因头发/裙摆夸大；
- 前后左右移动时模型正面正确；
- 相机近距离不会直接看到角色内部；
- 两客户端实例材质一致；
- 删除/替换模型不会破坏网络和碰撞字段。

# S25：Locomotion Animator——待机、八方向移动与空中状态

## 可见成果

人物能根据模拟速度播放 Idle、前后左右/斜向移动、起跳、下落和落地表现；动画不会推动 LogicRoot。

## 我负责完成

- 从 CharacterState 计算 Animator 表现参数；
- 设计最小 Base Layer 与 Blend Tree；
- 平滑 `MoveX`、`MoveY`、`Speed`，但不隐藏真正逻辑错误；
- 输出 `Grounded`、`VerticalSpeed`、`JumpStarted`、`Landed` 等表现信号；
- 本地与远端使用各自已稳定的逻辑/插值状态驱动 Animator；
- 禁止 Animator StateMachineBehaviour 直接发送网络命令；
- 添加参数调试面板。

## 建议 Animator 参数

实际名称在本课确认，语义通常包括：

| 参数 | 类型 | 来源 |
|---|---|---|
| MoveX | Float | 速度在角色局部 Right 上的投影 |
| MoveY | Float | 速度在角色局部 Forward 上的投影 |
| Speed | Float | 水平速度归一化 |
| Grounded | Bool | 权威/预测地面状态 |
| VerticalSpeed | Float | 垂直速度 |
| Jump | Trigger/短脉冲 | 起跳事件表现 |
| Land | Trigger/短脉冲 | 落地事件表现 |

## 你在 Unity 中操作

1. 在 `Assets/Game/Characters/Animation` 创建 Animator Controller。
2. 把 Controller 拖到角色模型 Animator 的 Controller 字段。
3. 确认 Animator 的 Avatar 指向 S24 正式角色 Avatar。
4. 第一版取消 `Apply Root Motion`。
5. 按我给的节点图创建 Base Layer、Locomotion Blend Tree 与 Air 状态；若适合由我生成 Editor 配置，我会写工具减少手工错误。
6. 将各动画 Clip 拖入指定 Motion 槽，并按动作真实方向设置 Blend Tree 坐标。
7. 按固定路线测试参数与动画。

## 固定调参顺序

1. 动作方向是否放对；
2. Clip 是否循环；
3. Blend Tree 阈值；
4. 参数平滑时间；
5. 状态过渡时长；
6. 起跳/落地触发窗口；
7. 最后才看脚滑和细节。

## 人工验收

- Idle 与八方向输入对应；
- 快速反向时不会长时间播错方向；
- 原地旋转与移动转身可读；
- Jump/Fall/Land 顺序正确；
- 远端动画不因快照微抖频繁切 Idle；
- 关闭 Animator 后逻辑移动和网络仍然正确。

## 完成记录

```text
状态：未开始
Animator Controller：
Clip 与方向表：
Blend Tree 阈值：
参数平滑：
Root Motion：关闭
```

# S26：瞄准层与 Animation Rigging 持枪

## 可见成果

角色下半身继续移动，上半身能够朝瞄准方向旋转，双手合理握持武器，头部/胸部 LookAt 有限制；不会因为看向身后而拧成不自然姿势。

## 本课才安装 Animation Rigging

开始前我会重新检查 Package。若尚未安装：

1. 打开 `Window > Package Manager`。
2. 选择 `Unity Registry`。
3. 搜索 `Animation Rigging`，安装 Unity 2022.3 提供的兼容版本。
4. 等待编译完成，记录实际版本。
5. 打开角色 Prefab，按实际 Package 菜单建立 Rig。

如果项目当时已有等价稳定方案，我会先解释差异，不会重复安装。

## 目标层级示意

```text
VisualRoot
  ModelRoot
  Rig
    AimRig
      SpineAimConstraint
      LeftHandIK
      LookAtConstraint
  RigTargets
    AimTarget
    LeftHandTarget
    LeftHandHint
```

实际约束组件根据模型骨骼和已安装版本决定。

## 我负责完成

- 建立 Aim Layer 和 Rig 权重驱动；
- 将 AimSolution 转为有角度限制的模型瞄准目标；
- 处理胸椎、头部与手臂的分配权重；
- 将左手目标绑定到 Weapon Prefab 的握把点；
- 区分探索、瞄准、换弹、死亡时的 Rig 权重；
- 防止远端 Aim 数据缺失时目标飞到世界原点；
- 添加骨骼轴向、目标和角度限制 Gizmo。

## 你在 Unity 中操作

代码和层级建立后，我会给逐字段绑定表，内容会包括：

- Animator 所在对象；
- Rig Builder 的 Rig Layers；
- Multi-Aim/Two-Bone IK 的约束骨骼；
- AimTarget、LeftHandTarget、Hint；
- 武器 LeftHandGrip 挂点；
- Rig 权重控制组件。

你需要在 Scene 视图中调 LeftHandGrip 到手掌贴合位置。这个视觉判断无法只靠代码完成。

## 人工验收

- 原地上下左右瞄准；
- 八方向移动中保持瞄准；
- 左右肩切换；
- 枪口贴墙；
- Jump/Fall 中瞄准；
- 远端观察瞄准方向；
- Aim 取消、死亡时 Rig 平滑归零；
- 头、肩、腕没有明显反折。

# S27：开火、换弹、受击与死亡动画

## 可见成果

权威/预测战斗事件能够驱动开火、换弹、受击和死亡动画；动画时长影响表现，但不会单独决定伤害、装弹完成或复活时间。

## 我负责完成

- 设计 Animator 上半身层、Avatar Mask 和必要状态；
- 将可靠战斗事件映射到一次性表现；
- 对预测开火与权威确认做去重；
- 让换弹动画跟随权威换弹状态，可被死亡/冲刺正确打断；
- 让死亡状态覆盖移动和 Aim Rig；
- 重生时重置 Animator、Rig、事件去重和残留 Trigger；
- 提供调试事件序号，排查重复播放或漏播。

## 你在 Unity 中操作

1. 创建或绑定 UpperBody Avatar Mask。
2. 在 Animator 新增 Weapon/Action Layer，设置正确 Blending 和权重。
3. 将 Fire、Reload、Hit、Death Clip 拖到指定状态。
4. 按我给的参数表创建 Trigger/Bool/Integer。
5. 检查 Reload 动画长度和服务器换弹时间是否协调；需要调整时先改表现速度或配置，不用 Animation Event 偷改弹药。
6. 测试死亡后 Animator 重新绑定与重生。

## Animation Event 的使用边界

可以用 Animation Event 触发纯表现细节，例如弹匣模型暂时隐藏、脚步音或局部粒子；不能用它：

- 决定服务器扣血；
- 决定弹药何时增加；
- 告诉服务器“我换弹完成”；
- 修改权威位置；
- 生成未经服务器认可的技能伤害。

## 人工验收

- 点射/连射动画与实际射速协调；
- 重复/重发网络事件不重复播强反馈；
- 换弹中死亡立即进入死亡状态；
- 受击不会永久卡住移动层；
- 死亡后不继续瞄准或持枪 IK；
- 重生后回到正常 Idle，旧 Trigger 不重播。

# S28：远端动画与 VisualRoot 平滑

## 可见成果

第二客户端看到的移动方向、瞄准、开火、换弹、受击和死亡表现与权威状态一致；网络微抖不会造成脚步状态疯狂切换或武器抖动。

## 我负责完成

- 让远端 Animator 只从插值后状态和可靠事件派生表现；
- 不直接同步 Animator 参数或 Animator State；
- 对速度、朝向、Aim Pitch/Yaw 使用合适平滑；
- 出生/重生/传送时清理旧快照和动画状态；
- 处理远端暂时不可见或低频复制时的表现降级；
- 为“逻辑根、插值根、视觉根、骨骼根”提供调试对比。

## 你执行的双客户端动作

- 八方向移动、突然停止、原地转向；
- 瞄准上下左右和肩位切换；
- 点射、连射和换弹；
- 移动中受击；
- 死亡、重生和立即移动；
- 100/200 ms 条件下重复上述动作。

## 判断问题属于哪里

- 逻辑根错误：位置/状态本身错误，先回第二或第三分卷；
- 插值根错误：远端目标不连续或缓冲选点错误；
- 视觉根错误：追赶参数过慢/过快；
- Animator 错误：参数正确但状态/Blend Tree 不正确；
- Rig 错误：基础动画正确但手、头、枪械约束异常。

# S29：UI、音效、VFX 与二次元视觉统一

## 可见成果

角色与武器拥有清楚的准星、命中确认、血量、弹药、受击方向、枪口/命中特效和基础音效；URP 画面有一致的二次元方向，但仍保持性能与多人可读性。

## 开始前你要准备

可以先使用占位，不要求一次买齐：

- 准星和 UI 图标候选；
- 开火、空弹、换弹、命中、受击、死亡音效候选；
- 枪口焰、普通命中、角色命中特效候选；
- 角色希望使用的色调与两三张视觉参考；
- 所有资源的来源和许可。

## 我负责完成

- 设计本地 HUD 与世界状态的边界；
- 将权威血量/弹药与预测反馈正确映射到 UI；
- 建立 VFX/Audio 事件播放、对象池和去重接口；
- 区分本地强反馈、远端弱反馈和观察者不应看到的信息；
- 检查 URP 材质、灯光、阴影、后处理与描边候选方案；
- 建立性能预算，不让每颗子弹 Instantiate/Destroy 大量对象；
- 解释哪些效果可立即预测，哪些必须等服务器确认。

## 你在 Unity 中操作

我会按实际 UI 方案给精确步骤，通常包括：

1. 创建/整理本地 HUD Canvas。
2. 把 Crosshair、HitMarker、Health、Ammo、Reload、NetworkDebug 放入明确节点。
3. 将 TextMeshPro/Slider/Image 引用逐项拖到 HUD Presenter。
4. 在 Weapon Prefab 绑定 AudioSource、Muzzle VFX 和 Impact Pool。
5. 在 Character Prefab 绑定受击/死亡 VFX 与 AudioRoot。
6. 调整 URP 材质和灯光时保留对比截图，不直接同时修改全部全局设置。

## 反馈权威表

| 反馈 | 可以立即预测 | 需要权威确认 |
|---|---|---|
| 本地枪口焰/开火声 | 是 | 服务器拒绝时不追求“倒放” |
| 准星普通扩散 | 是 | 由权威武器状态校正 |
| 命中确认/伤害数字 | 否或弱预测 | 是 |
| 对方受击/死亡 | 否 | 是 |
| 换弹开始表现 | 可预测 | 状态由服务器确认 |
| 弹药最终数量 | 可显示预测值 | 服务器拥有最终值 |

## 二次元视觉的第一版优先级

1. 角色轮廓和颜色对背景可读；
2. 受击、敌我和危险信息清楚；
3. 阴影和光照稳定；
4. 枪口与命中反馈统一；
5. 再考虑描边、Ramp、屏幕后处理和更复杂的风格化 Shader。

## 人工验收

- 本地、远端和观察者看到的信息权限正确；
- 预测开火不重复播放枪声/VFX；
- 命中与死亡反馈只在权威事件后出现；
- UI 在 16:9 常见分辨率可读；
- 100/200 ms 下弹药和血量最终一致；
- 连续射击一段时间没有明显粒子/音频对象不断增长；
- 场景无粉材质、强烈闪烁或严重过曝。
