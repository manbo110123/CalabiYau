# S16：第三人称跟随相机

## 可见成果

## 我会先检查

- S02 实际安装的 Cinemachine 版本；
- Main Camera、Character Prefab 的 CameraFollow/CameraLookAt；
- Input System 的 Look 数据和当前鼠标锁定逻辑；
- CharacterLab 的 CameraTests 墙体与狭窄区。

Cinemachine 不同主版本的组件名字和 Inspector 会变化。我会以项目已安装版本给出菜单，不让你照着其他版本教程找不存在的选项。

## 我负责完成

- 实现本地 Camera Mode/Controller，只消费 Look 输入；
- 设计探索相机的水平/垂直角度、俯仰限制和回中策略；
- 设置 Cinemachine 跟随、构图、阻挡和阻尼；
- 处理光标锁定、窗口失焦和暂停；
- 本地/远端实例只启用正确的相机控制；
- 添加相机目标、期望位置和碰撞命中的 Gizmo。

## 你在 Unity 中操作

本课会给出与实际版本一致的逐项步骤，通常包括：

1. 选中 Main Camera，确认挂有 Cinemachine Brain 或相应主相机组件。
2. 使用 Cinemachine 菜单创建虚拟相机。
3. 把本地角色的 `CameraFollow` 拖入 Follow 字段。
4. 把 `CameraLookAt` 或对应目标拖入 LookAt 字段。
5. 将相机碰撞查询限制在 `CameraObstacle`，忽略人物自身和 HitBox。
6. 把虚拟相机引用拖回本地相机控制组件。
7. 按参数表设置初始距离、肩偏移、俯仰限制、水平/垂直灵敏度和阻尼。

## 固定调参顺序

1. 跟随点高度；
2. 基础距离；
3. 水平肩偏移；
4. FOV；
5. 鼠标灵敏度；
6. 俯仰上下限；
7. 跟随/旋转阻尼；
8. 相机碰撞半径和恢复速度。

# S18：AimSolver 与第三人称双射线

## 可见成果

画面中能同时看到：相机中心射线选择的瞄准点、枪口到瞄准点的实际射线、最终可命中点。当枪口被近墙挡住时，子弹不会穿墙命中准星后的目标。

## 必须理解的语义

第三人称相机不在枪口位置。只用屏幕中心射线会导致枪口隔墙开火。第一版采用：

```text
相机中心射线 -> 得到想瞄的世界点
枪口/逻辑射击起点 -> 朝该世界点再次查询
第二条射线先撞墙 -> 最终命中墙
没有被挡 -> 最终命中目标或最大射程点
```

服务器不会接收客户端声称的命中对象。客户端发送受量化/校验的瞄准意图，服务器用权威射击起点和地图重新推导。

## 我负责完成

- 设计 `AimIntent` 和 `AimSolution`；
- 从屏幕中心生成相机射线并限制最大距离；
- 从权威可推导的射击起点生成第二条射线；
- 统一 LayerMask、Trigger 和自身忽略规则；
- 给相机射线、枪口射线、遮挡点和目标点使用不同颜色 Gizmo；
- 设计发给服务器的最小瞄准数据与容差校验；
- 添加近墙、无目标、超远目标和背向非法瞄准测试。

## 你在 Unity 中操作

1. 在 CharacterLab 的 CombatTests 放置近、中、远目标和一面近身薄墙。
2. 将本地 Camera、AimOrigin、后续 Weapon Muzzle、查询 LayerMask 拖到 Aim 组件。
3. 按我给出的值设置最大瞄准距离和自碰撞忽略范围。
4. Play 中开启 Debug Draw，观察两条射线。

## 人工验收

- 准星指向天空/无目标时有稳定最大距离点；
- 近墙挡枪口时最终射线命中墙；
- 相机看见但枪口看不见的目标不会被命中；
- 左右肩切换后语义仍一致；
- 相机极近和极远状态不产生 NaN 或反向射线；
- 双客户端的服务器命中结果与可视 Gizmo 能解释一致。

# S19：枪械资源、挂点与 Weapon Prefab

## 可见成果

一把枪正确挂在角色手中，拥有清楚的 `Muzzle`、弹壳/VFX/音频挂点和逻辑武器组件；更换模型不会改伤害代码。

## 开始前你要准备

- S03 选定的枪械模型，或接受先用灰盒枪；
- 枪械模型正面和握把方向截图；
- 如果已有角色持枪动画，准备预览截图；
- 不要求这时已经有最终枪口焰或声音。

## 目标 Prefab 层级

```text

  ModelRoot
  Muzzle
  ShellEject
  VfxRoot
  AudioRoot
  Debug
```

角色侧保留 `WeaponSocket`。正式模型出现后，WeaponSocket 会跟随右手/约定骨骼或 Animation Rigging 目标，但武器逻辑不写在手骨骼上。

## 我负责完成

- 建立武器定义、运行时武器状态和视觉组件的边界；
- 创建最小 Weapon Prefab 脚本；
- 让 AimSolver 使用逻辑 Muzzle/AimOrigin，而不是搜索对象名；
- 为挂点轴向画 Gizmo；
- 给出武器模型缩放、旋转和位置的调节方法；
- 解释哪些参数将来由服务器拥有。

## 你在 Unity 中操作

1. 将枪械模型放到我们自己的 Weapon Prefab 的 `ModelRoot` 下。
2. 只调整 ModelRoot 的局部位置/旋转/缩放，不歪掉 Prefab 根。
3. 把 `Muzzle` 放到枪管出口，蓝轴/指定轴向按本课约定指向射击方向。
4. 把 Weapon Prefab 拖到角色 `WeaponSocket`。
5. 将 Muzzle、VfxRoot、AudioRoot 等逐项拖到武器组件。
6. 保存角色和武器 Prefab，重新实例化确认引用不丢。

- 角色转身时武器跟随正常；

# S23：射击双客户端与弱网验收

## 可见成果

形成正常网络、100 ms、200 ms 下的完整射击记录，能解释客户端看到的预测表现与服务器最终结果为何不同。

## 我负责准备

- 运行协议、可靠请求、权威射线、遮挡、伤害、生命周期和延迟补偿测试；
- 给出 F3 面板应观察的请求序号、收据、重发、事件 ID、ACK 延迟和回溯 Tick；
- 为每次不一致定位到请求、查询或表现层；
- 验收后更新本卷和总状态。

## 你执行的固定矩阵

每种网络条件执行：

1. 静止目标正面对射；
2. 横向移动目标连续跟枪；
3. 枪口贴墙开火；
4. 目标刚进入掩体时开火；
5. 最后一发、空弹、换弹；
6. 开火后立即死亡；
7. 死亡与重生期间丢包；

- 本地开火反馈及时，服务器拒绝时能够解释和修正；
- 墙体遮挡始终优先于墙后人物；
- 重复请求不重复扣弹或伤害；
- 可靠结果最终到达且不会重复播放关键表现；
