# CalabiYau 3C 开发陪练手册：总目录与协作方式

> 文档版本：1.0  
> 建立日期：2026-08-29  
> 适用工程：Unity 2022.3.62f3c1、URP 14.0.12、.NET 8 独立 UDP 权威服务器  
> 使用方式：一课一次新对话，一次只完成一个可运行、可解释、可验收的小闭环

---

## 1. 这套手册解决什么问题

原《CalabiYau 二次元第三人称动作射击开发计划书》继续保留，用来解释项目最终要去哪里、技术上为什么这样选择。它是总纲，不要求你直接照着其中的大阶段独立完成。

这套“陪练手册”负责回答更具体的问题：

- 这一课开始前，你要准备什么素材或截图；
- Unity 中要打开哪个窗口、创建什么对象、拖拽哪个引用；
- 哪些代码由我检查和编写；
- 你需要理解代码中的哪几个概念；
- 编译、运行、双客户端和弱网分别怎样验收；
- 验收后把什么结果写回文档；
- 下一课是否已经具备进入条件。

你不需要提前看懂后面全部内容。每次只打开当前课次，并把该课的“新对话开场模板”发给我。

## 2. 我们怎样分工

### 2.1 你负责的部分

- 在 Unity 编辑器中完成需要视觉判断的操作，例如导入模型、选择骨骼、拖拽组件和调手感参数；
- 按清单寻找模型、动画、音效和 VFX，并保留许可证或来源记录；
- 把 Console 报错原文、Inspector 截图、Hierarchy 截图和运行现象告诉我；
- 执行我给出的人工验收动作，例如贴墙移动、斜坡起步、双客户端对射；
- 对“手感是否舒服、画面是否符合预期”做最终判断。

你不需要在不理解的情况下自己设计网络协议，也不需要独自猜代码应放在哪里。

### 2.2 我负责的部分

- 每课开始先读取当前代码、场景、Prefab、Package 和阶段记录，不凭旧文档猜实现；
- 告诉你这一步为什么做、有哪些方案、当前为什么选这一种；
- 在适合由代码完成时直接实现，并保持改动小、可回退；
- 给新增代码补上必要注释、测试或调试可视化；
- 精确告诉你 Unity 中需要添加哪些组件、每个字段拖什么、建议初值是多少；
- 编译并运行能够自动执行的测试；
- 在你人工验收后更新本课状态和下一课入口。

### 2.3 需要共同完成的部分

以下事情不能只靠代码，也不能只靠拖组件：

1. 我先实现最小规则和调试信息。
2. 你在 Unity 中绑定场景引用并操作验收。
3. 你反馈现象、数值和截图。
4. 我定位问题、修改代码或建议调参。
5. 直到本课完成标准全部满足，再进入下一课。

## 3. 每次新对话的标准流程

每一课都按下面七步进行：

1. **确认入口**：我检查上一课完成记录、Git 状态和工程是否能打开。
2. **概念预习**：我用当前功能解释 1～3 个必要概念，不先灌输整套理论。
3. **准备资源**：你按清单准备素材；拿不准时先发候选截图或资源说明，不盲目导入。
4. **实现最小闭环**：我写代码，你按明确步骤创建对象和绑定组件。
5. **代码讲解**：我按“输入 → 规则 → 输出 → 网络权威 → 调试点”解释本课代码。
6. **人工验收**：你执行固定动作并反馈结果；没有你的视觉验收，不把画面阶段标成完成。
7. **记录收口**：我更新状态、已知问题、关键参数和下一课入口。

遇到报错时，不要为了“继续教程”跳过。把以下内容发给我：

```text
1. 当前课次编号：
2. Unity Console 第一条红色错误的完整文本：
3. 复现步骤：
4. Hierarchy / Inspector 截图：
5. 你已经尝试过什么：
```

## 6. Package 安装原则

当前 `Packages/manifest.json` 已有 URP、Test Framework、TextMeshPro、uGUI 等基础包，但没有 Input System、Cinemachine 和 Animation Rigging。

我们不会一次装齐所有可能有用的包：

- S02 安装 **Input System** 和 **Cinemachine**；
- S26 真正开始程序化持枪和瞄准时，再安装 **Animation Rigging**；
- 不为了“以后可能需要”提前装联网框架、ECS、复杂角色控制器或技能框架；
- 版本以 Unity 2022.3 的 Package Manager 当时提供的兼容稳定版本为准，安装后把实际解析版本写回本课记录；
- 安装前保存工程并确认 Console 无红错，安装后重新编译、打开场景并做一次最小 Play 验证。

## 7. 素材准备原则

角色和动作不要求一开始就达到最终质量，但必须满足：

- 来源与许可证能够用于作品集展示；
- 模型能导出为 Unity 可识别的 FBX，骨骼可配置为 Humanoid；
- 第一版动画优先选择 **In-Place**，不让 Root Motion 决定网络权威位移；
- 枪械模型最好有明确的握把方向，能够自行建立 `Muzzle`；
- 动作最少覆盖 Idle、前后左右移动、跑动、跳跃、落地、持枪瞄准、开火、换弹、受击、死亡、冲刺；
- 所有下载文件先放在工程外的素材暂存目录，确认后再导入 `Assets/Art/...`，不要把整个商店示例工程拖进主项目。

## 10. 当前起点

- Unity 2022.3.62f3c1 迁移和双客户端人工验收已完成；
