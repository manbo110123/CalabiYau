# S07：创建 Input Actions 与输入可视化

## 可见成果

按下键鼠后，CharacterLab 调试面板能显示移动向量、视角增量、瞄准、开火、跳跃、冲刺、换弹和肩位切换状态；本课人物还不移动。

## 你在 Unity 中创建资源

1. 在 Project 窗口进入 `Assets/Game/Input`。
2. 右键 `Create > Input Actions`，命名为 `CalabiYauControls`。
3. 双击打开 Input Actions 编辑器。
4. 创建 Action Map：`Gameplay`。
5. 按本课代码设计创建 Actions：

| Action | Action Type | Control Type | 默认键鼠绑定 |
|---|---|---|---|
| Move | Value | Vector2 | WASD 的 2D Vector Composite |
| Look | Value | Vector2 | Mouse Delta |
| Aim | Button | Button | Right Mouse Button |
| Fire | Button | Button | Left Mouse Button |
| Jump | Button | Button | Space |
| Dash | Button | Button | Left Shift |
| Reload | Button | Button | R |
| ShoulderSwitch | Button | Button | V 或 Middle Mouse |

6. 保存 Asset。是否启用 `Generate C# Class` 由我根据当前工程代码结构决定，并告诉你类名和生成路径。

## 我负责完成

- 定义与 Unity 输入 API 无关的普通输入快照/命令结构；
- 实现本地输入读取器和调试显示；
- 区分持续值（Move、Look）与边沿事件（Jump、Dash、Reload）；
- 处理输入 Action 的启用和禁用生命周期；
- 避免在网络模拟中直接读取 `Keyboard.current` 或 `Mouse.current`；
- 添加最小测试，验证命令数据的归一化和按钮位。

## 你需要拖拽的字段

代码编译后，我会按实际组件给精确表。通常是把 `CalabiYauControls.inputactions` 或其中各 Action Reference 拖到 `LocalCharacterInput` 组件，并把输入读取组件挂在 `NetworkCharacter` 或专门的 `InputRoot`。

## 本课代码讲解重点

- 为什么设备输入不能直接成为网络协议；
- `performed/canceled` 回调与每帧轮询的区别；
- 为什么 Jump 必须保存“这一 Tick 是否按下”，而不是只读当前是否按住；
- 为什么 Look 是表现输入，而瞄准方向要转换成可发送的普通数据。

## 人工验收

- 单独按 W/A/S/D，调试向量方向正确；
- 斜向输入长度不会超过 1；
- 鼠标移动有正负方向，停止后不会持续漂移；
- Jump/Dash/Reload 单次按下只产生一次边沿；
- Alt-Tab、暂停或组件禁用后输入不会卡住；
- Tank SampleScene 仍可用。

# S08：离线相机相对平面移动

## 可见成果

CharacterLab 中的占位人物能按相机朝向在水平面移动、加速、减速和转身；不联网，不做墙体和斜坡。

## 我负责完成

- 将输入向量通过相机水平 Forward/Right 转为世界移动方向；
- 实现可调加速度、减速度、最大速度和转身速度；
- 分开逻辑朝向与 VisualRoot 朝向；
- 添加速度、期望方向和当前朝向 Gizmo；
- 给参数提供安全初值，但不假装初值就是最终手感。

## 你在 Unity 中操作

1. 把 S07 输入组件绑定到 Character Prefab。
2. 将 CharacterLab 的临时相机 Transform 拖到移动组件的 Camera Reference 字段。
3. 将 `LogicRoot`、`VisualRoot` 拖到对应字段。
4. 使用我给出的初值，例如步行/跑动速度、加减速度和旋转速度。
5. Play 后按固定路线测试，不边跑边随意改十个参数。

## 固定调参顺序

1. 最大速度；
2. 起步到最大速度的时间；
3. 松手停止时间；
4. 反向输入时的制动；
5. 视觉转身速度；
6. 低速输入死区。

每次只改一项并记录“原值 → 新值 → 现象”。

## 本课代码讲解重点

- 输入空间、相机空间和世界空间；

- `Update`、固定 Tick 与以后网络模拟的关系；

## 人工验收

# S09：抽取可共享的人物移动规则

## 可见成果

相同的初始状态和输入序列在客户端测试与 .NET 服务器测试中产生一致结果。画面上变化不大，但这是人物预测不长期发散的基础。

## 关键约束

服务器工程不能依赖 `UnityEngine`、`Transform`、`CharacterController`、`Physics` 或 Animator。共享层只使用普通 C# 数据、明确时间步长和我们控制的数学。

## 我负责完成

- 把平面加减速和朝向规则从 MonoBehaviour 抽到共享逻辑；
- 决定共享源码或等价实现的目录方式，并避免拷贝两份逐渐漂移；
- 将 Unity 的表现适配器变成“收集输入 → 调用模拟 → 应用结果”；
- 添加确定输入序列、不同帧率采样和边界值测试；
- 解释浮点误差的允许范围和我们此阶段的取舍。

## 你在 Unity 中操作

本课一般只需要重新绑定重构后的组件并做移动回归。我会明确哪些旧字段被替换、哪些参数迁到统一 Tuning。不要凭名字相似自行复制全部 Inspector 值。

## 本课代码讲解重点

- 纯规则层和 Unity 适配层；
- 固定 Tick 的 `deltaTime` 为什么不能来自随意的帧时间；
- 同一个 `Simulate(state, command, tuning, dt)` 如何服务服务器、预测和重放；
- 为什么动画、音效和粒子不能放进这个函数。

## 自动验收

- 30 Tick 输入在不同渲染帧率下得到相同模拟结果；

- 客户端和服务器使用相同协议数据语义。

## 你在 Unity 中绑定

- 客户端预测、重放和服务器权威调用同一移动规则；
- 给墙体、碰撞法线、Sweep 起终点和修正量画 Gizmo；
- 编写平地、正撞墙、斜撞墙、内角、外角、窄通道和初始重叠测试；

5. 把地图资源拖到网络启动和本地预测组件指定字段。

## 你执行的测试矩阵

每种网络条件都测试：平地变向、贴墙、内角、斜坡、台阶、跳跃、停止、重生。

| 条件 | 延迟 | 抖动 | 丢包 | 重点观察 |
|---|---:|---:|---:|---|
| 本机 | 约 0 ms | 0 | 0 | 基础规则与手感 |
| 轻度弱网 | 100 ms | 10～20 ms | 0～1% | 预测误差与远端平滑 |
| 明显弱网 | 200 ms | 20～40 ms | 1～3% | 校正、重放和最终一致 |

具体弱网工具配置要依据当前环境；不要把发送与接收方向重复叠加而误判成双倍延迟。

## 通过标准

- 本机条件下没有可稳定复现的规则错误；
- 100/200 ms 下本地输入仍立即响应；
- 校正能够收敛，未确认输入不会无限增长；
- 远端可读，没有长期穿墙或死亡后回拉；
- 地图版本不一致时能拒绝或清楚报错，而不是静默使用不同碰撞；
- 动态刚体和骨骼 HitBox 仍明确标记未实现。
