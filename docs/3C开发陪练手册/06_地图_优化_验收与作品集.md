# 第六分卷：地图、优化、验收与作品集

> 包含课次：S35～S38  
> 进入条件：S34 动作、技能与 HitBox 闭环通过  
> 本卷目标：停止横向增加系统，把已完成能力组合成可反复游玩、可测量、可构建、可讲解的作品集垂直切片

# S35：建立小型竞技地图

## 可见成果

一张支持双人移动、掩体射击、技能范围、出生安全和相机空间的正式小地图；服务器与客户端使用一致的静态碰撞/遮挡数据版本。

## 开始前你要准备

- 两三张你喜欢的二次元竞技训练场参考图；
- 希望的主题、主色和空间感觉；
- 已选环境素材包及许可，或接受先用现有原型材质做完整灰盒；
- 明确第一张地图只服务 2 人演示，不扩成大型地图。

## 地图设计最低要求

- 两个彼此不直接暴露的出生区；
- 至少两条主要交战路线；
- 近、中距离交战空间；
- 能验证相机贴墙、枪口遮挡、冲刺、跳跃和范围技能的几何；
- 掩体高度和通道宽度适合当前 Character Capsule；
- 不出现唯一制高点完全压制全图；
- 重新出生后有短时间观察和离开空间；
- 关键位置有清楚视觉地标。

## Package 原则

如果纯 Primitive 已不足以高效灰盒，本课可以评估 **ProBuilder**。只有确认确实需要时才通过 `Window > Package Manager > Unity Registry` 安装 Unity 2022.3 兼容版本，并记录实际版本。不会为了地图再引入完整第三方关卡框架。

## 我负责完成

- 根据人物实际尺寸给出通道、台阶、掩体和相机空间参考；
- 帮你把参考图收缩为可玩的平面布局；
- 建立地图静态碰撞导出、版本和校验流程；
- 建立 SpawnPoint 合法性、视线和出生选择查询；
- 添加地图调试视图：导航路线、视线、遮挡、出生半径、技能范围；
- 编写必要的出生/遮挡/地图版本测试；
- 检查环境资源对 URP、材质和性能的影响。

## 你在 Unity 中分三遍搭建

### 第一遍：纯灰盒

- 只用基本几何体/ProBuilder；
- 先验证尺寸、路线、相机和碰撞；
- 不摆小装饰，不做复杂灯光。

### 第二遍：玩法标记

- 放出生点、目标区、掩体、关键视线和技能测试点；
- Editor + Build 双客户端跑图；
- 修复卡角、相机挤压、无解视线和非法重生。

### 第三遍：美术替换

- 用正式环境模型逐步替换灰盒；
- 视觉模型与权威碰撞模型可以分离，但必须对齐；
- 每替换一块就重测碰撞与遮挡，不在最后一次性发现问题。

## 人工验收

- 两个方向完整跑图；
- 每处墙角、窄道、坡/阶和跳跃点；
- 近墙相机和左右肩切换；
- 所有主要掩体的枪口遮挡；
- 两人出生/重生至少十次；
- 冲刺和两个技能覆盖关键区域；
- 服务器地图版本不匹配时有明确失败；
- 视觉网格不能让玩家误判可通过/可射击区域。

# S36：最小游戏闭环

## 可见成果

从启动服务器和客户端开始，玩家能够进入地图、出生、战斗、死亡、重生、达到胜利条件、看到结算并重新开始，不需要开发者在 Inspector 手工复位。

## 第一版游戏循环

默认建议使用短时双人击杀赛：

```text
连接/握手
-> 等待玩家
-> 倒计时
-> 出生
-> 战斗
-> 死亡/重生
-> 达到击杀数或时间结束
-> 结算
-> 重新开始
```

不在本课制作账号、匹配大厅、房间列表或商业后端。

## 我负责完成

- 设计服务器权威 MatchState 与阶段 Tick；
- 定义开始条件、计分、胜利条件、重生和重开；
- 同步必要的比赛状态与可靠结算事件；
- 处理玩家中途加入/离开和人数不足；
- 建立 HUD、倒计时、比分、结算面板的数据接口；
- 添加状态转换、重复事件、重开清理和断线边界测试；
- 让所有状态可在服务器日志和 F3 面板中解释。

## 你在 Unity 中操作

- 创建/整理 Match HUD：等待、倒计时、比分、计时、死亡、结算；
- 将 TextMeshPro、Panel、按钮引用拖到 Match Presenter；
- 绑定本地玩家名/占位名和敌我颜色；
- 配置场景中的 SpawnPoint 组；
- 用 Editor + Build 从冷启动完整玩至少两局。

## 固定边界测试

- 只有一个玩家时；
- 第二玩家倒计时中加入；
- 战斗中玩家断开；
- 最后一击与比赛时间结束同 Tick；
- 玩家死亡事件与比赛结束竞争；
- 结算页面重复收到可靠事件；
- 重开后旧弹、旧技能、旧比分和旧快照是否清除。

# S37：性能、GC、带宽与稳定性优化

## 可见成果

形成一份基于 Profiler、服务器统计和网络数据的优化记录。每个优化都有“测量前 → 原因 → 修改 → 测量后”，而不是凭感觉重写代码。

## 我会先建立预算

预算要结合当前电脑和作品集目标，本课确认具体值。至少记录：

- 客户端目标帧率和 CPU/GPU 帧时间；
- Play 期间每帧 GC Alloc；
- 常态内存和长时间运行增长；
- 服务器 30 Hz Tick 耗时与尖峰；
- 每客户端上行/下行字节率与包率；
- 快照大小、可靠重发率和事件积压；
- 场景三角形、SetPass/Draw Calls、阴影和粒子峰值。

## 我负责完成

- 提供可重复的性能测试路线和统计脚本；
- 检查热路径分配、JSON 序列化、集合增长和日志刷屏；
- 分析快照/命令字段与发送频率，不夸大 `changeMask` 的现有能力；
- 对 VFX、投射物、弹孔、音频使用对象池或容量上限；
- 检查远端插值缓冲、历史状态和可靠事件账本的清理；
- 只实施有测量收益且不破坏可读性的优化；
- 运行回归测试并记录优化前后数据。

## 你在 Unity 中操作

1. 打开 `Window > Analysis > Profiler`。
2. 使用 Development Build + Autoconnect Profiler 验证真实 Build，不只看 Editor。
3. 按固定路线录制：空场、双人移动、连续射击、两个技能同时存在、死亡重生循环。
4. 保存 Profiler Capture 或关键截图。
5. 如果需要 Frame Debugger/Rendering Debugger，我会给当前 URP 的具体菜单与观察项。

## 长时间稳定性测试

- 服务器与两个客户端至少运行一段固定时间；
- 循环移动、开火、技能、死亡和重生；
- 观察内存、对象数量、未确认输入、快照缓冲、可靠事件、投射物和 VFX Pool；
- 检查断开重连或重开比赛后的清理；
- 保存峰值与结束值。

## 不接受的“优化”

- 没有测量就把 JSON/UDP 全部替换成新网络框架；
- 为了少量性能牺牲服务器权威正确性；
- 把所有对象变成单例或静态集合；
- 关闭调试信息却不保留 Development 开关；
- 用降低测试压力掩盖持续增长。

# S38：最终回归、Build、演示与作品集收口

## 可见成果

得到可交付 Windows Build、服务器运行说明、正常网络/弱网演示视频、架构图、测试记录、README 和一套你能独立讲清的项目材料。

## 我负责完成

- 检查所有阶段的“已完成/未完成”表述是否与代码和验收一致；
- 运行完整服务器和共享规则测试；
- 建立最终双客户端与弱网回归矩阵；
- 整理启动脚本/命令、Build 目录和配置说明；
- 更新 README、项目复习指南、架构图和技术取舍；
- 帮你写作品集项目描述和面试讲解，但不夸大动态刚体、完整差分复制等未实现功能；
- 检查 Git 工作区并提出里程碑提交/标签建议；
- 汇总已知问题与下一版本候选，不在收口阶段继续加功能。

## 你负责录制和主观验收

### 演示视频建议顺序

1. 10～15 秒展示最终角色、地图和战斗画面；
2. 本地操作：移动、跳跃、冲刺、相机、瞄准、开火、换弹、技能；
3. 双客户端：远端移动、伤害、死亡、重生与结算；
4. 墙体遮挡、人物 HitBox 和延迟补偿 Gizmo；
5. 100/200 ms 下 F3 面板、预测校正与最终一致；
6. 简短架构图：命令、服务器 Tick、快照、预测/重放、插值；
7. 自动测试与性能数据一闪而过，证明不只是画面 Demo。

### 最终手感验收

- 连续玩至少两局，不打开 Inspector 修参数；
- 找一名不了解项目的人试玩，记录第一次卡住的位置；
- 确认操作提示、准星、血量、弹药、冷却和结算信息足够；
- 确认错误断线或服务器未启动时有可理解提示；
- 确认视频中不会暴露私人路径、账号或无关窗口。

## 最终回归矩阵

- 冷启动服务器 + Editor + Build；
- 两个 Windows Build（若条件允许）；
- 正常网络、100 ms、200 ms；
- 人物移动、碰撞、跳跃、冲刺；
- 相机、肩位、枪口遮挡；
- 射击、弹药、换弹、HitBox；
- 投射物和范围技能；
- 死亡、重生、计分、结算、重开；
- 长时间运行和断线边界；
- Unity Console、服务器日志和测试全部无未解释错误。

## 作品集事实边界

最终文档要准确区分：

- 已完成：由代码、测试和人工验收共同证明；
- 简化实现：例如有限人数、JSON、简化 AOI、受控 HitBox；
- 未来方向：动态服务器物理、完整差分压缩、大厅匹配等；
- 不得把计划书中的目标写成已经存在的能力。
