# S30：建立显式动作状态机

## 可见成果

移动、跳跃、瞄准、开火、换弹、冲刺、受击和死亡之间的允许/禁止关系可在调试面板中看到；不会再由多个 Bool 在不同脚本中互相打架。

## 我负责完成

- 盘点当前所有状态与隐含互斥规则；
- 区分 `LifeState`、`LocomotionState`、`ActionState` 与 WeaponState；
- 设计最小显式状态和进入/退出条件；
- 将状态推进放入固定 Tick 权威/预测规则；
- 让 Animator 只消费状态，不成为状态真相；
- 增加当前状态、状态起始 Tick、拒绝原因和剩余时间调试；
- 添加非法转换、死亡打断、重生重置和重复命令测试。

## 状态设计原则

- 不为了“通用”创建几十层抽象；
- 每个状态必须有明确拥有者和退出条件；
- 时间以 Tick/明确秒数推进，不依赖动画播完回调；
- 客户端可以预测允许的状态，但服务器有最终决定权；
- 重放状态转换不能重复播放 VFX/音效；
- 瞄准等可并行姿态不一定要和所有动作塞进同一个枚举。

## 你需要共同确认

我们会用表格逐项确认体验规则，例如：

| 当前行为 | 是否能移动 | 是否能瞄准 | 是否能开火 | 是否能跳跃 | 是否能被死亡打断 |
|---|---|---|---|---|---|
| Reload | 可减速移动/待定 | 可/待定 | 否 | 否/待定 | 是 |
| Dash | 受控 | 取决于设计 | 否/待定 | 否 | 是 |
| HitReact | 可减速/待定 | 可/待定 | 可/待定 | 否 | 是 |
| Dead | 否 | 否 | 否 | 否 | 已终止 |

这些是玩法决定，不应由我在代码中偷偷替你做。若你没有偏好，我会先给简单、可解释的默认值。

## 你在 Unity 中操作

- 在调试面板开启 State 显示；
- 将 ActionState Presenter 绑定到 Animator 和 UI；
- 根据我给的事件映射表检查每个状态表现；
- 执行固定按键组合，记录拒绝原因是否符合设计。

## 人工验收

- 换弹中连续按开火/跳跃/冲刺；
- 冲刺开始同 Tick 被击杀；
- 空中尝试不允许的动作；
- 受击与换弹竞争；
- 死亡和重生清理全部旧状态；
- 100 ms 下预测状态被服务器拒绝时能回到合法状态。

# S31：可预测、服务器权威的冲刺

## 可见成果

按下冲刺立即获得清楚的移动和视觉反馈；服务器验证冷却、方向、距离和碰撞；远端看到可读冲刺；弱网下最终位置一致。

## 开始前共同决定

- 冲刺类型：固定距离短闪、持续时间加速、翻滚或滑步；
- 能否空中使用；
- 是否可中途转向；
- 冲刺期间能否开火/瞄准；
- 是否有无敌帧。第一版建议没有无敌帧，避免同时引入伤害时间窗复杂度；
- 碰墙是停止、滑动还是反弹。第一版建议停止/受控滑动，不反弹。

## 我负责完成

- 将 Dash 输入边沿接入 CharacterCommand；
- 定义冲刺状态、起始 Tick、持续 Tick、速度曲线和冷却；
- 复用人物 Capsule Sweep 和碰撞滑动；
- 在客户端预测并在服务器重算；
- 校正被墙提前终止或服务器拒绝的冲刺；
- 同步远端状态和一次性表现事件；
- 添加冷却绕过、重复请求、冲刺穿墙、死亡打断和重放测试。

## 你在 Unity 中绑定

- Dash 动作 Clip；
- Trail/VFX 占位或正式 Prefab；
- Dash Audio；
- 冷却 UI；
- Animator Dash 参数与状态；
- VisualRoot 倾斜/镜头冲击参数（若本课启用）。

## 固定验收路线

- 平地向前、向后、向侧面冲刺；
- 贴墙正冲和斜冲；
- 内角冲刺；
- 坡面向上/向下冲刺；
- 台阶边缘和空中按键；
- 冷却期间连按；
- 冲刺中受击/死亡；
- 100/200 ms 双客户端观察。

# S32：最小技能数据与权威投射物

## 可见成果

角色能够释放一个直线投射物技能：本地立即播放起手反馈，服务器生成并推进权威投射物，命中或超时后通过可靠结果表现。

## 为什么现在才做技能框架

此时项目已经有输入命令、状态机、权威 Tick、碰撞查询、可靠事件、预测表现和对象池。技能框架可以从一个真实技能抽取共同数据，而不是先造一个不知道要服务什么的庞大系统。

## 我负责完成

- 定义最小 `SkillDefinitionData`、`SkillRuntimeState` 和 CastCommand；
- 明确服务器可读取的技能配置来源，不让权威数值只存在 Unity ScriptableObject；
- 处理施法前摇、冷却、资源消耗和状态互斥；
- 在服务器固定 Tick 推进投射物位置与 Sweep；
- 定义客户端预测发射表现和权威实体对应方式；
- 处理命中、超时、重复请求、死亡取消和对象池；
- 添加高速穿透、墙体优先、重复伤害和弱网测试。

## 你要准备

- 技能视觉概念：颜色、形状、大小；
- 一个发射 VFX、飞行 VFX、命中 VFX 候选，允许先占位；
- 一个释放动作或接受复用现有上半身动作；
- 希望的射程、速度、冷却和伤害感觉，数值由本课测试调整。

## 你在 Unity 中绑定

- Skill Input Action；
- 角色 SkillOrigin；
- 投射物 Visual Prefab；
- Cast/Travel/Impact VFX 与 Audio；
- 技能图标和冷却 UI；
- Animator Cast 参数。

我会逐项说明本地预测对象和权威对象如何对应，避免场景中出现两颗长期并存的视觉弹。

## 本课代码讲解重点

- 投射物实体与投射物视觉的区别；
- 高速物体为何使用 Sweep 而不是只检查新位置；
- 客户端可预测释放反馈，但不能决定伤害；
- SkillDefinition 的 Unity 编辑版本如何转为服务器可用普通数据；
- 可靠“命中结果”和高频“飞行状态”为什么可以采用不同同步策略。

## 人工验收

- 静止、移动、跳跃、瞄准时释放；
- 近墙释放；
- 高速弹打薄墙；
- 目标与墙重叠视线；
- 冷却中连按；
- 释放后立即死亡；
- 100/200 ms 下预测视觉能与权威结果收敛；
- 投射物销毁后对象池和事件记录不增长失控。

# S34：人物 HitBox 与延迟补偿升级

## 可见成果

射击可以区分人物身体区域；服务器拥有权威 HitBox 简化层级和历史姿态，延迟补偿在明确时间上限内回溯，不依赖客户端骨骼 Transform 作为真相。

## 分级实施

这是一项高风险功能，按以下级别推进：

1. 单 Capsule 命中：当前基线，确认迁移无回归；
2. 头部球体 + 躯干 Capsule：先得到身体分区；
3. 少量肢体 Capsule：仅在演示确有价值时增加；
4. 完整逐骨骼命中：不作为第一版默认目标。

## 我负责完成

- 定义服务器可复现的 HitBox Pose 数据，而不是同步所有骨骼矩阵；
- 从权威角色根、姿态枚举和少量 Aim 参数推导头/躯干命中体；
- 保存受限历史缓冲并在射击时间回溯；
- 静态墙体与人物历史命中比较正确排序；
- 定义头部/躯干伤害倍率与合法范围；
- 给当前与回溯 HitBox 使用不同颜色 Gizmo；
- 添加边界 Tick、历史不足、墙后头部、死亡姿态和重复结果测试。

## 你在 Unity 中操作

1. 在 Character Prefab 的 `HitBoxes` 节点创建调试形状/映射组件。
2. 将 Head、Chest 等骨骼 Transform 只作为客户端视觉校准参考拖入字段。
3. 调整服务器简化 HitBox 的相对偏移与尺寸，使它们覆盖稳定身体区域。
4. 在 CharacterLab 使用正面、侧面、蹲/空中（如有）固定靶姿势检查。
5. 开启历史回溯 Gizmo，录制延迟条件下的命中画面。

## 必须保持的边界

- 客户端骨骼位置不能直接成为服务器命中答案；
- 回溯时间有上限，超出历史不能无限补偿；
- 回溯人物不代表回溯世界所有动态物体；
- 当前若没有服务器权威动态刚体，文档继续明确这一限制；
- 不同步 Animator State 来假装还原完整历史姿态。

## 人工验收

- 正面/侧面头部与躯干；
- 墙后只露头；
- 快速横移目标；
- 跳跃中的目标；
- 射击时目标刚死亡或重生；
- 0/100/200 ms 比较命中；
- 超过最大回溯窗口的请求被限制；
- 调试射线、墙体和回溯 HitBox 能解释结果。
